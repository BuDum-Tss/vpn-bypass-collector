# VPN Bypass Collector

Расширение для Chrome/Edge и фоновый агент для Windows, которые решают, какие сайты открывать
**через VPN, а какие мимо него**. Сделано под клиент hidemy.name (WireGuard/AmneziaWG, OpenVPN), но работает
с любым VPN, который создаёт отдельный сетевой адаптер.

Два списка, оба всегда действуют:

| список | что в нём |
|--------|-----------|
| **Через VPN** | сайты, которые должны открываться через VPN (заблокированные, замедляемые) |
| **Мимо VPN** | сайты, которые должны открываться без VPN (российские сервисы, сайты, которые не пускают VPN) |

Всё, чего нет в списках, идёт **через VPN по умолчанию**, а **российские IP-сети агент пускает напрямую сам**
(8 тысяч подсетей из RIPE): `.ru`, `.рф`, `.su` и любые сайты на российских адресах работают без VPN без всяких
записей.

## Как сайт попадает в список

Каждый новый сайт **проверяется в обоих путях**: агент на несколько секунд ставит на его IP временный маршрут
сначала напрямую, потом через VPN и делает настоящий HTTPS-запрос с именем сайта (блокировки зависят от пары
«IP + имя»). По замерам расширение решает:

| напрямую | через VPN | результат |
|----------|-----------|-----------|
| открывается | не открывается / заглушка «отключите VPN» | **мимо VPN** (и выводятся IP-диапазоны его сети) |
| не открывается / медленно / только проверка браузера | открывается | **через VPN** |
| открывается | открывается | «через VPN», пометка «работает везде»: маршрут не нужен, сайт идёт по умолчанию |
| не открывается | не открывается | в «Проверки → не открывается нигде», повтор через час |

«Медленно» — это замедление (например, YouTube ~140 кбит/с напрямую): ошибкой оно не проявляется, проверка
скорости его ловит. Проверка браузера Cloudflare сама по себе VPN не винит: ответ считается «хуже» только в сравнении
с другим путём.

Проверка запускается для каждого нового сайта, который вы открыли (основная страница), для сайта из списка, если он
перестал открываться, и по кнопке **«+ текущий сайт»**. Идёт она только при включённом VPN и запущенном агенте,
по одному сайту за раз, около 10–15 секунд на сайт.

## Из чего состоит

1. **Расширение** (`manifest.json`, `background.js`, `content.js`, `popup.*`) — замечает новые сайты, ставит их на
   проверку, раскладывает по спискам, показывает статус, отправляет списки агенту.
2. **Агент** (`agent/`) — фоновый процесс Windows: держит маршруты в таблице маршрутизации, проверяет сайты
   (`/probe`), даёт локальный HTTP на `127.0.0.1`. Подробности — в [agent/README.md](agent/README.md).

## Возможности

- **Единая кнопка «+ текущий сайт»**: проверка в обоих путях и размещение в нужный список.
- **Метка «🚫 блокирует VPN»**, результат проверки (что напрямую, что через VPN, время, скорость) и **IP-адреса**
  у каждой записи; перенос между списками одной кнопкой.
- **Статус применения** («✓ Применено: мимо VPN N маршрутов…») и кнопка **«Обновить у агента»**.
- **Стартовый набор «через VPN»**: Claude, Google, YouTube, Facebook, Instagram, ИИ-сервисы, X, Discord, LinkedIn,
  мессенджеры и др.; для Google, Meta и Telegram — IP-диапазоны целиком (эти сервисы отдают сотни меняющихся
  адресов, маршруты «по домену» пропускали бы часть трафика).
- **Резервная копия** всего состояния (Настройки → Сохранить / Загрузить): расширение, загруженное из другой папки,
  получает другой ID и пустое хранилище. «Чистое» расширение не затирает списки агента: оно сначала забирает их.
- Вкл/выкл VPN кнопкой, страна и IP.
- Данные версий 1.x и 2.x переносятся автоматически (сайт, оказавшийся в обоих старых списках, уходит на проверку).

## Установка

### Расширение (без магазина)

1. `chrome://extensions` или `edge://extensions` → **Режим разработчика**.
2. **Загрузить распакованное** → выбрать папку репозитория.

> ID расширения зависит от пути к папке. Если папку перенесёте, сохраните состояние (Настройки → Сохранить) и
> загрузите его в «новом» расширении.

### Агент

Нужны Windows и Node.js LTS. В **PowerShell от администратора**:

```powershell
cd agent
Copy-Item config.example.json config.json   # свой конфиг (в git не попадает)
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Создаётся задача планировщика «VPN Bypass Agent» (старт при входе, права администратора, скрытое окно).
Удаление — `uninstall.ps1`. Если агент что-то сломал с сетью: `node agent\vpn-bypass-agent.mjs --cleanup`.

Первое применение (около 8 тысяч маршрутов российских сетей) идёт через системный API и занимает секунды;
до его завершения российские сайты идут через VPN, то есть работают, просто не напрямую.

## Как это работает

- **Маршруты по IP.** Для списка «мимо VPN» и российских подсетей агент добавляет маршруты через физический шлюз
  (длиннее маршрутов туннеля, поэтому побеждают). Записи «через VPN», попавшие внутрь широкого диапазона «мимо VPN»,
  получают точечный маршрут в туннель (иначе, например, YouTube утонул бы в чужом диапазоне).
- **Заглушки VPN** (страница открывается, но требует отключить VPN — Ozon, hh): для такого сайта расширение через DoH
  и RIPE Stat выводит IP-диапазоны его сети, чтобы весь блок шёл мимо VPN. Крупные облака/CDN целиком не
  разворачиваются — для них берётся только /24.
- **Определение VPN и шлюза** — по адаптеру (`vpnAdapterMatch`) и аппаратному адаптеру, а не по виду адреса.
- **Путь по умолчанию** можно переключить на «напрямую» (Настройки), но он менее надёжен: замедление не даёт
  ошибок, а крупные сервисы меняют IP.

## Ограничения

- Маршрутизация идёт по IP: домены на общих CDN затягивают в список больше, чем один сайт; диапазон может захватить
  чужой сайт.
- Проверка отвечает на вопрос «открывается ли главная страница»; сайт, у которого ломается только часть сервисов
  (например, видео), она может счесть рабочим.
- Только Windows и IPv4. Агенту нужны права администратора.
- Проверено на AmneziaWG (hidemy.name); OpenVPN и другие протоколы должны работать, но не проверялись.

## Разработка

```powershell
npm test            # логика фонового скрипта на подставном chrome-API (без браузера и агента)
```

Агент можно проверять без изменения таблицы маршрутов: `"dryRun": true` в `config.json`.
Список российских подсетей обновляется `node agent/tools/update-ru-ranges.mjs`.

## Файлы

| файл | назначение |
