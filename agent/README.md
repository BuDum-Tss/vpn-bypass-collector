# VPN Bypass Agent

Фоновый агент: держит маршруты, чтобы каждый сайт шёл нужным путём (**через VPN** или **мимо него**), и проверяет,
как открывается сайт в каждом из путей. Работает только когда VPN включён; при выключении маршруты снимаются.

## Почему так, а не «в исключения hidemy.name»

У hidemy.name 3.0 нет открытого API и нет отдельного UI «split tunneling по сайтам».
Но клиент **сам** делает обход именно так — в логах видно:

```
Applied Xray LAN bypass with 2 forced VPN host route(s)
route.exe ADD 89.149.199.92 MASK 255.255.255.255 192.168.0.1   ← адрес VPN-сервера мимо туннеля
Modified WireGuard AllowedIPs to exclude LAN ranges            ← тот же приём для WireGuard/AmneziaWG
```

Агент повторяет этот механизм (`hidemy.name_VPN.Core.Providers.VpnBypassProvider`):
для каждого IP нужного домена добавляет `route add <ip> mask 255.255.255.255 <шлюз_LAN> metric 1`.
Такой /32-маршрут длиннее префикса, чем сплит-дефолт туннеля (`0.0.0.0/1`), поэтому
трафик к этим адресам идёт напрямую. Kill-switch у вас выключен (`KillSwitch=0`),
для WireGuard hidemy использует режим «exclude LAN» без catch-all — так что маршруты не блокируются.

Плюс: перезапуск VPN не нужен, маршруты применяются мгновенно.

## Как VPN и физический шлюз определяются

`detectVpn()` в [vpn-bypass-agent.mjs](vpn-bypass-agent.mjs):
- VPN «включён», если у VPN-адаптера (`vpnAdapterMatch`, по имени или описанию) есть широкие маршруты (≤ /16)
  либо старый признак: `0/1`, `128/1`… с next-hop `10.x`. Собственные маршруты агента при этом не считаются;
- физический шлюз — default-маршрут на **аппаратном** адаптере (Wi-Fi/Ethernet, `Get-NetAdapter -Physical`), а не по
  виду адреса: у домашних сетей и мобильных точек доступа шлюз как раз `10.x`.

Проверить руками: `node vpn-bypass-agent.mjs --status`

## Установка

Нужен Node.js LTS (`node -v`). Затем **в PowerShell от администратора**:

```powershell
cd agent
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Создаётся задача планировщика **«VPN Bypass Agent»** — старт при входе в систему,
с правами администратора, в скрытом окне (через `run-hidden.vbs`).

Удаление: `powershell -ExecutionPolicy Bypass -File .\uninstall.ps1` (снимет задачу и маршруты).

## Два списка и путь по умолчанию

| список | файл (`%APPDATA%\vpn-bypass\`) | ключ конфига |
|--------|--------------------------------|--------------|
| **direct** — должны открываться мимо VPN | `domains.txt` | `listPath` |
| **vpn** — должны открываться через VPN | `whitelist.txt` | `whitelistPath` |

(Имена файлов исторические: `domains.txt` — список direct, `whitelist.txt` — список vpn.)

Путь по умолчанию (`default`) — куда идёт всё, чего нет в списках: `vpn` (рекомендуется) или `direct`. Маршруты нужны
только **противоположной** стороне:

| default | явные маршруты | дополнительно |
|---------|----------------|---------------|
| `vpn` | для списка direct + **российские подсети** (`data/ru-ranges.txt`) через физический шлюз | — |
| `direct` | для списка vpn в туннель | «половинки» туннельных маршрутов через физический шлюз (всё остальное напрямую) |

Записи умолчательной стороны, попавшие **внутрь широкого диапазона** другой стороны, получают точечный маршрут
(YouTube из списка «через VPN» не тонет в диапазоне «мимо VPN»). Если одна и та же запись есть в обоих списках,
выигрывает явная (не умолчательная) сторона.

Список и путь по умолчанию присылает расширение (`POST /apply`, ждёт применения). Убрали запись — маршрут снимается
сразу; запись есть, но её IP перестал резолвиться — маршрут держится `staleHours`. Перед перезаписью файла непустой
список копируется в `<файл>.bak`. Формат файлов — по записи в строке; `#` — комментарий; домены, IP и `IP/CIDR`.
`staticEntries` в конфиге — постоянные записи списка direct.

Агент следит за файлами списков и за `config.json` — правки применяются за ~1 c без перезапуска.

## Российские подсети

`data/ru-ranges.txt` — российские IPv4-сети (RIPE Stat, ~8600 CIDR): при `default=vpn` они идут напрямую, поэтому `.ru`,
`.рф`, `.su` и любые сайты на российских адресах работают без VPN. Обновление: `node tools/update-ru-ranges.mjs`
(ничего не меняет в системе, только пишет файл). Отключить: `"regionDirect": false`.

## Пакетные операции с маршрутами

`route.exe` на каждый маршрут — запуск процесса (~0.15 с): восемь тысяч подсетей — минуты. Поэтому большие наборы
идут через [tools/route-batch.ps1](tools/route-batch.ps1) (`CreateIpForwardEntry2`/`DeleteIpForwardEntry2`, секунды).
При старте раскладка структуры сверяется с реальной таблицей (`-SelfTest`, только чтение); неудавшееся в пачке
добивается `route.exe`, при сбое пакетного режима агент работает как раньше. Статус: поле `batchApi` в `/status`.

## Проверка сайта (`POST /probe`)

`{host}` → замеры по двум путям. Агент резолвит домен, на несколько секунд ставит временный /32-маршрут на его IP
сначала напрямую, потом через VPN и делает HTTPS-запрос с именем сайта (SNI). Для каждого пути отдаёт: `reached`,
`status`, `ttfb`, `kbps` (скорость по образцу), `stub` (явное «отключите VPN / недоступно в вашем регионе»),
`challenge` (проверка браузера Cloudflare/антибот), `kind` (`ok`/`timeout`/`reset`/`tls`/`dns`…). Проверки идут
в общей очереди с пересчётом маршрутов; временные маршруты снимаются всегда, остатки после аварии чистятся при старте.
Решение о списке принимает расширение.

## Протоколы hidemy

Агент привязан не к протоколу, а к VPN-адаптеру (`vpnAdapterMatch`, по имени или описанию) и его
широким маршрутам (≤ /16): подходит и WireGuard/AmneziaWG (в т.ч. через Xray-ретранслятор), и OpenVPN.
Проверено на AmneziaWG. Если у адаптера другое имя — поправьте `vpnAdapterMatch` (regex, можно `hidemy|Amnezia`).

## Локальный HTTP (для расширения) — `127.0.0.1:35777`

`/status` отвечает мгновенно, из кэша (детект VPN и гео обновляются в фоне); долгие операции
(`powershell`, `route.exe`, DNS) выполняются асинхронно и сервер не блокируют.

| метод | путь | что делает |
|-------|------|-----------|
| GET  | `/status` | `{vpnUp, gw, default, mode, routes, baseRoutes, region, batchApi, apply:{ok,default,entriesDirect,entriesVpn,regionTargets,routes,added,removed,overrides,ms,at,busy,error}, geo, adapters, sig}` — из кэша, мгновенно |
| GET  | `/list?kind=direct\|vpn[&fileOnly=1]` | записи списка (`fileOnly` — без `staticEntries`) |
| POST | `/apply`  | `{default, direct:[…], vpn:[…], sig}` — записать списки, задать путь по умолчанию, **дождаться применения**, вернуть итог. Принимает и формат расширения 2.x `{mode, blacklist, whitelist}` |
| POST | `/refresh`| принудительный проход без смены списков, возвращает итог |
| POST | `/probe`  | `{host}` — проверка сайта напрямую и через VPN (см. выше) |
| POST | `/resolve`| `{names:[…]}` → `{ips:{имя:[ip,…]}}` (кэш 5 мин) — для показа IP в расширении |
| POST | `/list`   | (совместимость) `{entries:[...]}` — перезаписать список direct |
| POST | `/vpn`    | `{action:"connect"\|"disconnect"}` — Enable/Disable-NetAdapter на адаптерах VPN |

Слушает только `127.0.0.1`. `apiPort` и `vpnControl` — в `config.json`.

## Вкл/выкл VPN

`vpnControl: true` разрешает `POST /vpn`. **disconnect** = `Disable-NetAdapter` на
адаптерах, чьё имя подходит под `vpnAdapterMatch` (туннель падает сразу).
**connect** = `Enable-NetAdapter` + `Start-Service 'hidemy.name VPN Watcher'`; сам
hidemy переподключается (в его настройках `Autoconnect=1`). Если hidemy упорно
поднимает соединение обратно — поставь `vpnControl: false` и переключай в самом клиенте.
`config.json` тоже перечитывается на лету — добавить домен в `staticEntries` и сохранить
достаточно, перезапуск не нужен.

**Поддомены и антибот.** Расширение группирует по базовому домену (`ifmo.ru`), но
поддомены живут на других IP (`isu.ifmo.ru`, `api.ozon.ru`, `st.ozone.ru` — каждый
отдельно). Если часть поддоменов идёт напрямую, а часть через VPN, антибот-защита
(у Ozon — «Antibot Challenge Page») видит один сеанс с двух разных IP и зацикливает
проверку. Лечение — гнать мимо VPN **весь блок провайдера**, а не отдельные хосты:

```json
"staticEntries": ["185.73.192.0/21"]   // весь диапазон Ozon (AS202422)
```

`staticEntries` принимает домены, голые IP и `IP/CIDR`. Узнать блок сайта:
`nslookup <домен>` → взять IP → посмотреть его на bgp.he.net / whois (`route:` / `NetRange`).

## config.json

| ключ | по умолчанию | смысл |
|------|--------------|-------|
| `listPath` | `%APPDATA%\vpn-bypass\domains.txt` | файл списка «мимо VPN» (direct) |
| `whitelistPath` | `%APPDATA%\vpn-bypass\whitelist.txt` | файл списка «через VPN» (vpn) |
| `mode` | `blacklist` | устаревший: путь по умолчанию до первого `/apply` (`blacklist` = VPN, `whitelist` = напрямую) |
| `regionDirect` | `true` | при `default=vpn` российские подсети (`data/ru-ranges.txt`) идут напрямую |
| `regionFile` | `` | свой файл со списком CIDR вместо `data/ru-ranges.txt` |
| `dryRun` | `false` | `true` — не менять таблицу маршрутов, только писать команды в лог (для проверки) |
| `staticEntries` | `[]` | всегда-обход, помимо файла (домены / IP / CIDR) |
| `enableIPv6` | `false` | добавлять и AAAA-маршруты |
| `reResolveMinutes` | `15` | как часто перерезолвивать домены (CDN меняют IP) |
| `vpnPollSeconds` | `20` | как часто проверять статус VPN |
| `staleHours` | `24` | сколько держать маршрут для IP, который перестал резолвиться |
| `routeMetric` | `1` | метрика добавляемых маршрутов |
| `vpnAdapterMatch` | `hidemy` | regex по имени VPN-адаптера |
| `apiPort` | `35777` | порт локального HTTP (только `127.0.0.1`) |
| `vpnControl` | `true` | разрешить `POST /vpn` (кнопка вкл/выкл в расширении) |
| `geoTtlSeconds` | `30` | кэш ответа гео-сервиса (`ipwho.is`) |

## CLI

| команда | действие |
|---------|----------|
| `node vpn-bypass-agent.mjs` | демон (обычно запускает задача планировщика) |
| `… --status` | показать конфиг, статус VPN, список, активные маршруты |
| `… --once` | один проход и выход (для проверки) |
| `… --cleanup` | снять все маршруты, очистить state и выйти |

Логи и состояние: `C:\ProgramData\vpn-bypass-agent\` (`agent.log`, `state.json`, `agent.lock`).
`agent.lock` хранит PID — второй экземпляр агента при живом первом просто выходит.

## Ограничения

- Маршруты **эфемерные** (без `-p`): после перезагрузки исчезают, агент добавит их заново при входе.
- Домены на «толстых» CDN (Cloudflare/Akamai/Fastly) резолвятся в общие IP —
  в обход уйдёт больше, чем один сайт. Это плата за маршрутизацию по IP.
- Если hidemy когда-нибудь включит WFP kill-switch, маршруты перестанут спасать —
  тогда пришлось бы вместо этого править `AllowedIPs` конкретного туннеля.
- Только IPv4 по умолчанию.
