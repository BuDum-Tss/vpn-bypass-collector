# VPN Bypass Collector

Расширение для Chrome/Edge и фоновый агент для Windows, которые решают, какие сайты пускать
**через VPN, а какие — мимо него**. Сделано под клиент hidemy.name (WireGuard/AmneziaWG, OpenVPN),
но работает с любым VPN, который создаёт отдельный сетевой адаптер.

Два режима, у каждого свой независимый список:

| режим | через VPN идёт | сайты собираются, когда… |
|-------|----------------|--------------------------|
| **Чёрный список** | всё, **кроме** записей списка | сайт не открывается при включённом VPN (или открывается, но блокирует VPN) |
| **Белый список** | **только** записи списка | сайт не открывается напрямую (без VPN) |

## Из чего состоит

1. **Расширение** (`manifest.json`, `background.js`, `content.js`, `popup.*`) — следит за сетевыми
   ошибками, копит кандидатов, показывает статус VPN и применения списка, отправляет списки агенту.
2. **Агент** (`agent/`) — фоновый процесс Windows: держит маршруты в таблице маршрутизации и даёт
   локальный HTTP на `127.0.0.1` для расширения. Работает только пока VPN включён.
   Подробности — в [agent/README.md](agent/README.md).

```
сайт не открылся → расширение → POST /apply → агент резолвит имена → route add → трафик идёт нужным путём
```

## Возможности

- **Два независимых списка** со своими исключениями и переключателем автодобавления. Исключения
  («никогда не добавлять автоматически») действуют только при включённом автодобавлении.
- **Единая кнопка «+ текущий сайт»**. В чёрном списке при включённом VPN расширение проверяет, открывается
  ли сайт: открывается — значит, он блокирует VPN (страница-заглушка, антибот), и для него выводятся
  IP-диапазоны провайдера; не открывается — обычная запись.
- **Пометка «🚫 блокирует VPN»** и **IP-адреса** у каждой записи (резолвит агент).
- **Статус применения**: «✓ Применено: N записей → M адресов» и кнопка **«Обновить у агента»**, которая
  отправляет списки и ждёт, пока агент их применит.
- **Стартовый набор белого списка**: Claude, Google, YouTube, Facebook, Instagram, ИИ-сервисы, X, Discord,
  LinkedIn, Twitch, мессенджеры и др. Для Google, Meta и Telegram добавлены IP-диапазоны целиком: эти
  сервисы отдают сотни меняющихся адресов, и маршруты «по домену» пропускали бы часть трафика.
- **Резервная копия** всего состояния расширения (Настройки → Сохранить / Загрузить). Расширение,
  загруженное из другой папки, получает другой ID и пустое хранилище — копия это переживает.
- Вкл/выкл VPN кнопкой (`Disable/Enable-NetAdapter`), страна и IP.

## Установка

### Расширение (без магазина)

1. `chrome://extensions` или `edge://extensions` → **Режим разработчика**.
2. **Загрузить распакованное** → выбрать папку репозитория.

> ID расширения зависит от пути к папке. Если папку перенесёте — сохраните состояние (Настройки →
> Сохранить) и загрузите его в «новом» расширении. «Чистое» расширение не затирает список агента: оно
> сначала забирает то, что у агента уже есть.

### Агент

Нужны Windows и Node.js LTS. В **PowerShell от администратора**:

```powershell
cd agent
Copy-Item config.example.json config.json   # свой конфиг (в git не попадает)
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Создаётся задача планировщика «VPN Bypass Agent» (старт при входе, права администратора, скрытое окно).
Удаление — `uninstall.ps1` (снимает задачу и маршруты). Если агент что-то сломал с сетью:
`node agent\vpn-bypass-agent.mjs --cleanup`.

## Как это работает

- **Чёрный список.** Для IP записей агент добавляет `route add <ip> <шлюз_LAN>`: маршрут длиннее
  маршрутов туннеля, поэтому трафик идёт напрямую. Так делает и сам hidemy.name.
- **Белый список.** Агент перекрывает «широкие» маршруты туннеля (у WireGuard это `/2`, `/3`, `/5`…)
  узкими половинками через физический шлюз — всё идёт напрямую, — а IP записей направляет в туннель.
- **Заглушки VPN** (страница открывается, но требует отключить VPN — Ozon, hh и т.п.): ловятся по тексту
  контент-скриптом или добавляются кнопкой; расширение через DoH и RIPE Stat выводит IP-диапазоны сети
  сайта. Крупные облака/CDN целиком не разворачиваются — для них берётся только /24.
- **Определение VPN** — по адаптеру (`vpnAdapterMatch`) и его широким маршрутам, а не по протоколу.

## Ограничения

- **Маршрутизация идёт по IP.** Домены на общих CDN затягивают в список больше, чем один сайт, а у гигантов
  адреса меняются — поэтому для Google и Meta нужны диапазоны целиком. Обратная сторона: диапазон Google
  может захватить чужой сайт (заглушка `mail.google.com` перехватила YouTube).
- Отличить «заблокировано из-за VPN» от «сайт лежит» надёжно нельзя — поэтому есть порог попаданий,
  пометка «снова открывается» и исключения.
- Детект заглушек шлёт имя хоста в `dns.google` и `stat.ripe.net`. Отключается тумблером в настройках.
- Только IPv4 по умолчанию; только Windows.
- Режим белого списка проверен на AmneziaWG; OpenVPN и другие протоколы должны работать, но не проверялись.

## Разработка

```powershell
npm test            # логика фонового скрипта на подставном chrome-API (без браузера)
```

Агент можно проверять без изменения таблицы маршрутов: `"dryRun": true` в `config.json` — команды
`route` только пишутся в лог.
